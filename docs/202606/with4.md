# 视频介质安全加密方向分析

## 一、先厘清一个关键错位：你的系统不在"加密域"

你这套 `my-webui` 视频大模型系统，工作在**明文本地视频域**——直接用 OpenCV 读裸 `mp4/mov`、抽帧喂给 Ollama、把分析结果写成明文 `.analysis.md`。**全链路零加密、零版权保护、零水印**。

而腾讯视频 / Netflix 的"介质安全加密"是另一个完全不同的域：它保护的是**内容资产本身不被盗取/盗录/盗播**。两者的关系是——主流流媒体在"受保护域"工作，你的系统在"明文域"工作。要把二者"结合分析"，本质是问：**一份视频从生产到消费，介质安全加密做在哪几层、当前往哪个方向演进，而 AI 分析应该嵌在哪一层。**

介质安全可分为三层 + 一个正交维度：

| 层 | 关注点 | 代表技术 |
|---|---|---|
| 生产域（制作/入库） | 母版不外泄 | 存储加密（KMS 信封）、TPN 可信合作网络 |
| 分发域（转码/打包/传输） | 传输不被截、下载不可用 | CENC 统一加密、HLS/DASH 加密、防盗链、TLS |
| 消费域（播放器/终端） | 解密只在授权设备、防盗录 | Multi-DRM、TEE 硬解、HDCP、反截屏、取证水印 |
| 正交：内容安全 | 内容是否合规/真实 | AI 审核、Deepfake 检测、C2PA 溯源 |

## 二、消费域：当前主流加密方向（Netflix vs 腾讯视频 TVKPlayer）

这是介质安全最核心、演进最快的一层。腾讯视频 TVKPlayer 的加密类型枚举 `TVKVodCryptoType` 把当前格局表达得很清楚：

```
kNone=0  kCommon=1(普通DRM)  kTaiHe=2(数字太和)  kChacha20=3
kFairPlay=4(iOS)  kWidevine=5(Android)  kChinaDrm=6  kChinaDrm2_0=7
kPlayReady=8(Win)  kMultiDrm=9  kTXVDrm=10(腾讯视频自研DRM)
```

对照 Netflix，可以提炼出**四个明确方向**：

**方向 1：CENC 统一加密 + Multi-DRM 一源多端**
- Netflix：一份内容用 CENC（Common Encryption，CTR/CBC 模式）加密一次，通过 Widevine（Android/Chrome）、PlayReady（Windows/Xbox）、FairPlay（Apple）三套 DRM 分发不同终端，密钥经 CPIX 协议交换。
- 腾讯视频：完全同构——TVKPlayer 用 Feature 接口模式（`TVKVodWidevineDrmFeature` / `TVKVodFairplayDrmFeature` / `TVKVodChinaDrm20Feature`），加 `kMultiDrm` 多方案组合 + `kTXVDrm` 自研 DRM + `kChinaDrm2_0`（国内合规强制）。
- **方向本质**：加密与封装解耦，"加密一次、多端解密"，并叠加国产化 DRM（ChinaDRM 2.0 是政策要求）。

**方向 2：硬件可信 + 安全分级（清晰度与安全级别绑定）**
- 行业铁律：**SD/HD 走软件级，4K/UHD 强制硬件级 TEE 解密**。Widevine 分 L1（硬件 TEE）/L2/L3（软件），UHD 必须 L1。
- 腾讯视频文档明确：`security_level` 安全级别、`max_number_of_sessions`、设备 DRM 能力查询（`GetDrmCapability`），按"L1 硬件解密 / L3 软件解密"动态选择，4K 不达标降级播放。
- **方向本质**：把解密密钥与明文帧关进芯片 TEE，CPU/内存里取不到明文，从根上防内存抓取。

**方向 3：取证水印（Forensic / 会话水印）——防盗录的主战场**
- Netflix 对原创/4K 内容用**会话级前向水印（A/B watermarking）**：给每个会话嵌入不可见的唯一标识，泄露后能溯源到具体账号/设备。这是当前**增长最快**的方向，因为 DRM 防不住"对着屏幕翻拍"。
- 腾讯侧：TVKPlayer 播放器能力含**软水印、动态水印**；腾讯云数据万象提供**数字水印**（"将字符串隐藏在视频中，不易探知、不破坏观赏性，用于版权追溯"）。
- **方向本质**：从"事前防解密"转向"事后可溯源"，DRM + 取证水印组合拳。

**方向 4：终端防录屏 + 输出保护 + 鉴权纵深**
- 反截屏特性（TVKPlayer 的"反截屏特性：防止录屏截图"）、HDCP 输出链路保护、防盗链（腾讯视频 AppKey + referer/g_tk 校验 + 下载版权/地域校验责任链）、传输层 httpdns 用 DES/AES 加密防劫持。

## 三、分发域：后端介质处理流水线的加密方向（腾讯云数据万象）

你问的"后端介质处理"，腾讯云数据万象（CI）给出了标准范式——**加密在转码环节内联完成**：

```
上传COS → 触发转码(转码过程中加密) → 从密钥管理模块取密钥
→ 加密后的 .m3u8/.ts 写回COS → CDN分发
→ 播放器带签名token(JWT) 请求解密密钥 → 解密播放
```

要点与方向：
- **加密与转码一体化**：HLS 标准加密 / DASH 加密在转码模板里勾选开启，自适应码率（一源生成多码率）同时打包加密。
- **密钥与内容分离**：内容存 COS，密钥存独立密钥管理模块；播放时用 JWT（`HMACSHA256(header.payload, key)`）签发临时令牌换密钥，实现"按次/按人/按时效"授权。
- **存储域加密**：母版/敏感数据用 AES-GCM-256、国密 SM4-GCM、KMS 信封加密（DEK 由 CMK 加密、明文密钥只在内存）。
- **AI 已内联进处理流水线**：数据万象转码侧已经带"视频标签、智能封面、精彩集锦、质量评分、人声分离"等 AI 能力——**这正是你的系统的对标物和归宿**。

---

## 四、正交维度：内容安全（这才是视频大模型的主场）

"介质安全"有两层含义，容易混淆：
- **内容保护（Content Protection）**= 防盗版 = DRM/加密/水印 → 你的系统**目前完全不涉及**。
- **内容安全（Content Safety）**= 内容是否合规/真实 = 鉴黄/暴恐/敏感识别、Deepfake 检测、AIGC 溯源 → **这才是视频大模型的天然战场**。

当前内容安全的加密相关方向：
- **C2PA / Content Credentials**：给视频附加密签名的"内容凭证"，记录来源与编辑链，对抗 AIGC 伪造——这是 2025 后最热的"介质真实性"方向。
- **加密域 AI 分析 / 机密计算**：在 TEE / 同态加密环境里对**加密视频**做推理，分析时不解密、不落明文，兼顾"要分析"与"要保密"。

---

## 五、结论：当前介质安全加密的总体方向（5 点）

1. **加密一次、多端解密**：CENC 统一加密 + Multi-DRM（Widevine/PlayReady/FairPlay）+ 国产 ChinaDRM 2.0 强制并行。
2. **安全级别下沉到硬件**：清晰度与 TEE 硬件解密级别绑定，4K/UHD 必须 L1，明文帧不出芯片。
3. **从"防解密"扩展到"可溯源"**：会话级取证水印（A/B watermarking）成为防盗录关键，DRM 管不到的翻拍由水印兜底。
4. **加密内联进后端处理流水线**：转码即加密、内容与密钥分离、JWT 令牌动态授权，AI 标签/审核与加密在同一工作流并行。
5. **介质"真实性"成为新战线**：C2PA 内容凭证 + 加密域/机密计算 AI，应对 AIGC 造假与隐私合规。

## 六、你的视频大模型系统应嵌入的落点

把你的系统放进上面的链路，它**不该去做 DRM/加密**（那是播放器和转码侧的事），而应嵌入两个高价值环节：

| 落点 | 做什么 | 对应方向 |
|---|---|---|
| 后端处理流水线（对标数据万象 AI 能力） | 转码同时产出 AI 标签/智能封面/事件时间线/敏感内容审核 | 第四点（AI 内联流水线）+ 内容安全 |
| 内容安全 / 溯源 | VLM 做鉴黄暴恐识别、Deepfake 检测；分析报告加 C2PA 数字签名做溯源 | 内容安全 + 介质真实性 |
| 处理过程自身的介质安全（你现在的短板） | 中间帧/缓存/报告**落盘加密**（AES-GCM/KMS 信封）、密钥不硬编码、TEE 内推理 | 生产域存储加密 + 机密计算 |

特别提醒一个现实安全债：上一轮已发现 `analyze-remote.sh` 曾硬编码 API Key、`.analysis.md`/抽帧截图全部明文落盘、`~/.video_analysis_cache` 明文缓存。**你的系统在"处理过程的介质安全"上目前是裸奔的**——如果要处理有版权/隐私的视频，这是首先要补的：抽帧产物与报告加密落盘、密钥走 KMS/环境变量、敏感视频处理在隔离环境内完成。
