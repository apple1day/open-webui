## 一、当前能否用本地大模型分析本地视频？—— 可以，且已经实现

项目在 `videos` 分支上已经搭好了一条**完全离线**的本地视频分析流水线：

| 环节 | 实现 | 关键文件 |
|---|---|---|
| 抽帧 | OpenCV（4 种策略：auto/count/interval/scene 镜头检测） | `backend/open_webui/routers/video_analysis.py`、`scripts/video_tasks.py` |
| 逐帧视觉描述 | Ollama VLM（`qwen2.5-vl:7b`/`minicpm-v`/`llava`）或 MLX（`Qwen2.5-VL-7B-4bit`） | 同上 |
| 音频转写 | faster-whisper（本地权重 `models/whisper-base-local/`） | 同上 |
| 文本汇总 | `qwen2.5:14b` / MLX `Qwen2.5-7B` | 同上 |
| 输出 | `<视频名>.analysis.md` + 可选 `.srt` | `_write_report()` |

流程是：**抽帧 → 逐帧 VLM 描述 → 音频转写 →（拼时间线）文本汇总 → 落盘报告**。前端 `/video` 页面通过 SSE (`/api/v1/video/analyze/stream`) 实时显示进度。所以**本地分析本地视频的能力是现成可用的**，运行 `start-video-analysis.sh` 即可。

## 二、能否用在线大模型优化本地离线模型？—— 可以，但当前代码没接，需要新增

现状：**全程没有任何云端 API 调用**，两套后端（Ollama / MLX）都是本机推理。要"用在线模型优化本地能力"，有三条可落地的路径，按改造成本排序：

1. **在线模型做"汇总层"（最低成本，最实用）**
   逐帧视觉仍用本地 VLM（保护原始画面不出本机），但把拼好的纯文本时间线送给在线强模型（GPT-4o / Claude / Gemini / 通义千问）做最终汇总润色。改动点很小：`video_analysis.py` 的汇总环节目前写死调 Ollama `/api/chat`，抽象出一个 `summary_backend` 即可（脚本里已有 `--summary-backend` 雏形，扩展一个 `openai` 分支即可）。
    - 优点：画面帧不出本机，只有文字摘要上云，**隐私/合规风险最低**。

2. **在线 VLM 做"困难帧增强"**
   本地 VLM 先跑，对置信度低或关键帧（scene 切换点）再调在线 VLM 复核。属于混合推理，代码改造中等。

3. **在线模型蒸馏 / 微调本地模型（真正"优化能力"）**
   用在线大模型批量生成高质量标注（帧描述 + 摘要），作为训练数据微调本地 Qwen2.5-VL（LoRA）。这是"用在线模型提升离线模型能力"的本义，但属于离线训练流程，和当前推理代码是两套工程。

> 注意：方案 1/2 会让"完全离线"这一设计前提被打破，需要在 UI/配置上明确告知用户哪些数据会上云。
